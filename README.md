# Интернет-магазин «Web-Larёk»

«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component

Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`

#### Класс Api

Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter

Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` - хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

##### Данные

Интерфейс `IProduct`, описывает структуру объекта товара.

- `id` — уникальный идентификатор товара (строка).
- `description` — описание товара (строка).
- `image` — ссылка или путь к изображению товара (строка).
- `title` — название товара (строка).
- `category` — категория, к которой относится товар (строка).
- `price` — цена товара, может быть числом или отсутствовать (null).

Интерфейс `IBuyer` описывает структуру объекта покупателя.

- `payment: TPayment` — способ или данные оплаты.
- `email: string` — электронная почта покупателя.
- `phone: string` — номер телефона покупателя.
- `address: string` — адрес покупателя.

###### Модели данных

Класс `Products` отвечает за хранение массива всех товаров и за работу этого массива.
У класса есть конструктор, который пинимает объект - `events`.

Методы:
-метод `saveProducts` принимает параметры `products: IProduct[]` . Сохраняет массив товаров, переданный в параметре и вызывает событие `"catalog:changed"`.
-метод `getProducts` не принимает параметры. Возвращает массив всех товаров.
-метод `getProductById` принимает параметры `id: string`. Возвращает товар по его id.
-метод `saveSelectedProduct` принимает параметры `product: IProduct`. Сохраняет товар для подробного отображения и вызывает событие `"card:selected"` с этим товаром.
-метод `getSelectedProduct` не принимает параметры . Возвращает товар для подробного отображения.

Класс `Basket` хранит массив товаров, выбранных покупателем. Он отвечает за управление содержимым корзины, позволяя добавлять, удалять и очищать товары.

Методы:
-метод `getProducts` не принимает параметры. Возвращает массив всех товаров.
-метод `addProduct` принимает параметры `product: IProduct`. Добавляет товар в корзину и вызывает событие "basket:changed".
-метод `deleteProduct` принимает параметры `id: string`. Удаляет товар из корзины и вызывает событие "basket:changed".
-метод `clear` не принимает параметры. Очищает корзину и вызывает событие "basket:changed".
-метод `getFullPrice` не принимает параметры. Возвращает стоимость всех товаров в корзине.
-метод `getProductCount` не принимает параметры. Возвращает количество товаров в корзине.
-метод `hasProductById` принимает параметры `id: string`. Проверяет наличие товара в корзине по его id.

Класс `Buyer` хранит данные покупателя. Отвечает за сохранение, получаение, очистку и валидацию этих данных. Конструктор принимает объект событий `events`.

- Методы:
  - `savePayment(payment: TPayment)` — сохраняет способ оплаты и генерирует событие `"buyer:changed"` с указанием, что изменилось поле `"payment"`.
  - `saveAddress(address: string)` — сохраняет адрес и запускает событие изменения адреса.
  - `saveEmail(email: string)` — сохраняет email и запускает событие изменения email.
  - `savePhone(phone: string)` — сохраняет телефон и запускает событие изменения телефона.
  - `getData(): IBuyer` — возвращает объект с текущими данными покупателя.
  - `clearData(): void` — очищает все данные покупателя и запускает валидацию.
  - `validation()` — проверяет заполненность всех полей и возвращает объект с ошибками валидации по каждому полю, если данные пусты.

###### Слой коммуникации

Класс `ProductApi` наследуется от базового класса `Api` и служит для работы с продуктами через HTTP-запросы к серверу.

- Метод `getAllProducts()`:
  - Выполняет GET-запрос по пути `"/product/"`.
  - Возвращает промис с объектом, содержащим массив продуктов `items` и общее число продуктов `total`.
  - Тип возвращаемого значения: `Promise<{ items: IProduct[]; total: number }>`.

- Метод `postOrder( Partial<TOrder>)`:
  - Выполняет POST-запрос по пути `"/order/"` с переданными данными заказа.
  - Принимает частичный объект заказа (`Partial<TOrder>`), что позволяет отправлять неполные данные.
  - Возвращает промис с полным объектом заказа `TOrder`.


###### Классы представления

`Card<T>` — универсальный (generic) компонент карточки товара, который расширяет базовый класс `Component`, принимая в качестве данных тип, объединяющий свойства `title` и `price` из интерфейса `IProduct` с дополнительным типом `T`.

- **Тип `TCard`** — это тип, включающий только два обязательных свойства из интерфейса `IProduct`: `title` (название товара) и `price` (цена).
- **Класс `Card<T>`** наследуется от `Component`, где данные включают свойства из `TCard` и дополнительные свойства типа `T`.

- Есть сеттеры для обновления контента элементов:
  - `title` — устанавливает текст заголовка карточки.
  - `price` — устанавливает текст с ценой в формате «<цена> синапсов» или «Бесценно», если цена пустая или отсутствует.



`CardBasket` расширяет общий класс `Card` с типом `TCardCart`

- Наследует от `Card<TCardCart>`, что означает, что он работает с данными типа `TCardCart`.
- Конструктор принимает:
  - `container`: HTML-кнопку, контейнер карточки.
  - `events`: объект для управления пользовательскими событиями (`IEvents`).

Сеттеры

- `index` — изменяет текстовое содержимое `indexElement`, то есть отображает порядковый номер товара в списке корзины.
- `id` — задаёт значение `itemId`, тем самым привязывая к карточке конкретный товар по его строковому ID.


`CardCatalog` описывает UI-компонент карточки каталога товара, расширяя абстрактный или базовый класс `Card<TCardCatalog>`.

 **Типы и интерфейсы:**
  - `CategoryKey` — тип ключей объекта `categoryMap`, используется для типизации ключей категорий.
  - `TCardCatalog` — тип данных, основанный на интерфейсе `IProduct`, включает только поля `'image'` и `'category'`.


- **Свойство `category` (сеттер):**
  - Устанавливает текст содержимого в элемент категории.
  - Для каждого ключа из `categoryMap` переключает CSS-класс у `categoryElement` так, что класс, соответствующий текущему значению категории, активен, а остальные удалены.
  
- **Свойство `image` (сеттер):**
  - Устанавливает изображение в элемент `imageElement`.
  - В URL изображения меняет расширение на `.png` (отбрасывая последние 3 символа в исходной строке), добавляя базовый `CDN_URL`.
  - Загружает изображение вызовом метода `setImage`, передавая элемент, сформированный URL и заголовок карточки.





Описание класса `CardPreview`

- Наследуется от `Card<TPreviewCard>`, где `TPreviewCard` — тип с выбранными свойствами `image`, `category`, `description` из продукта.
- В конструкторе:
  - Инициализируются внутренние элементы карточки из контейнера DOM.
  
- Сеттеры:
  - `text` — изменяет текст кнопки.
  - `disabled` — включает или отключает кнопку, добавляя/удаляя класс `"button_disabled"`.
  - `image` — задает изображение карточки, преобразуя путь картинки и вызывая метод `setImage`.
- Метод `setCanAddToBasket` управляет состоянием кнопки и текста в зависимости от наличия товара в корзине и доступности цены.



Описание класса Gallery и интерфейса GalleryData

- **interface GalleryData**  
  Определяет тип данных для компонента `Gallery`. Содержит единственное свойство:  
  `catalog` — массив элементов `HTMLElement`, представляющих содержимое галереи.

- **class Gallery extends Component<GalleryData>**  
  Класс `Gallery` наследуется от базового класса `Component` с параметром типа `GalleryData`.

- **constructor(container: HTMLElement)**  
  Конструктор принимает DOM-элемент-контейнер, который передаётся в конструктор родителя. Контейнер служит корневым элементом для галереи.

- **protected set catalog(items: HTMLElement[])**  
  Сеттер для свойства `catalog`, который обновляет содержимое контейнера.  
  Метод заменяет всех текущих детей контейнера на новые элементы из массива `items` с помощью `replaceChildren`.




**Класс `Header`**:
  - Наследуется от базового класса `Component` с типом пропсов `IHeader`.
  - В конструкторе принимает:
    - `events: IEvents` — объект для обработки и генерации событий.
    - `container: HTMLElement` — корневой элемент, внутри которого размещён компонент.

- **Свойства:**
  - `counterElement: HTMLElement` — DOM-элемент, в котором показывается значение счётчика корзины.
  - `basketButton: HTMLButtonElement` — кнопка, по которой пользователь открывает корзину.

- **Методы и логика:**
  - В конструкторе через `ensureElement` находят в контейнере элементы с классами `.header__basket-counter` (счётчик) и `.header__basket` (кнопка корзины).
  - На кнопку `basketButton` добавляется обработчик клика, который вызывает событие `"basket:open"` через переданный объект `events`.
  - Сеттер `counter` обновляет текст внутри `counterElement`, показывая текущее числовое значение счётчика.



Описание класса `Modal`


- **Конструктор:**
  - Принимает `container` (элемент, содержащий модальное окно) и объект `events`.
  - Через функцию `ensureElement` находит в контейнере элементы кнопки закрытия и блока контента.
  - Добавляет обработчик клика на кнопку закрытия для вызова метода `close`.
  - Добавляет обработчик клика по самому контейнеру: если клик на фоне модального окна (вне содержимого), окно закрывается.

- **Сеттер `content`:**
  - Позволяет установить новое содержимое модального окна, заменяя текущее дочернее содержимое `contentElement` на переданный элемент.

- **Метод `open`:**
  - Показывает модальное окно, добавляя CSS-класс `.modal_active`.
  - Генерирует событие `'modal:open'` через объект `events`.

- **Метод `close`:**
  - Скрывает модальное окно, убирая CSS-класс `.modal_active`.
  - Очищает содержимое модального окна.
  - Генерирует событие `'modal:close'`.

- **Метод `setCloseHandler`:**
  - Позволяет добавить кастомный обработчик на закрытие окна, который срабатывает как на кнопку закрытия, так и на клик по фону модального окна.

- **Метод `clearContent`:**
  - Удаляет всё содержимое из блока контента модального окна.
